# MTNIMA website prototype — handoff guide

This repository rebuilds the bilingual (Arabic/French) Drupal 11 prototype of
the redesigned website of the Ministry of Digital Transformation and
Administrative Modernization (Mauritania). **It is a prototype, not the
official site** (https://mtnima.gov.mr/). It has not been deployed, has not had
a security review, and is **not production-ready**.

Last verified: 27 October 2026, by rebuilding the site from the repository
files in a separate DDEV project with an empty database (see
[Verification](#verification)).

## 1. Set up a local copy

Requirements: Git, Docker, [DDEV](https://docs.ddev.com/en/stable/) 1.25 or
later, a bash shell (Linux, macOS or WSL), and internet access (Composer
packages and Drupal's Arabic/French translations are downloaded).

```sh
git clone <private repository URL> mtnma
cd mtnma
scripts/setup-site.sh
ddev launch /ar            # or: ddev launch /fr
ddev drush user:login      # one-time admin login link
```

`scripts/setup-site.sh` takes about 5 minutes and does the following:

1. `ddev start` and `ddev composer install` (Drupal core and modules).
2. Points Drupal at the committed configuration by adding
   `$settings['config_sync_directory'] = '../config/sync';` to the local,
   uncommitted `web/sites/default/settings.php`.
3. Installs Drupal from `config/sync` (`drush site:install --existing-config`),
   then runs `drush config:import` once more (the installer skips English when
   the default language is Arabic; the second import adds it).
4. Downloads Drupal's Arabic and French interface translations
   (`locale:check`, `locale:update`).
5. Runs `web/modules/custom/mtnma_site/scripts/seed.php`, which creates all
   content: the front page, the 16 section pages, 7 news articles, 5 digital
   services, the main and footer menus, and the 9 content images (copied from
   the theme). It then builds the search index.
6. Imports the theme's own translations
   (`web/themes/custom/mtnma/translations/{ar,fr}.po`).

The script refuses to run against a DDEV project that already has a site.
`scripts/setup-site.sh --reinstall` replaces it: it saves a DDEV snapshot
first (`ddev snapshot --list`), then erases and rebuilds the database.

Expected messages: Drupal reports 3 skipped strings with "disallowed or
malformed HTML" in its own Arabic translation file (`drupal-11.4.11.ar.po`).
They come from Drupal's translation server and do not affect the site.

## 2. Accounts

- The setup gives the built-in admin account (user 1, name `admin`) a random
  32-character password that is never shown or stored. Sign in with a
  one-time link: `ddev drush user:login`.
- Give each person their own account; don't share user 1:
  1. Signed in as admin, go to *People → Add user* (`/fr/admin/people/create`),
     enter the person's email, and tick the **Administrator** role
     (`مدير الموقع` / *Administrateur*). That role has every permission.
  2. Let them set their own password from a one-time link:
     `ddev drush user:login --name=<username>`. Avoid typing passwords on the
     command line, where they end up in the shell history.
- On any environment that others can reach, once personal admin accounts work,
  block user 1 (`ddev drush user:block admin`) or keep its password in a
  password manager only.
- There is no Editor role yet. Decide which permissions editors need before
  creating one. Do not grant the *Page layout HTML (administrators)* text format
  to non-admins: it accepts raw HTML, including scripts.
- The original developer's local copy used the password `admin`. It is not
  part of this handoff; anyone who has such a copy should change it
  (`ddev drush user:password admin '<new password>'`).

## 3. What you receive

| Path | What it is |
|---|---|
| `config/sync/` | The full Drupal configuration: modules, theme, Arabic/French/English languages and URL prefixes, content types and fields, the 3 listings (Views), search settings, text formats, roles and permissions, and configuration translations. |
| `web/themes/custom/mtnma/` | The theme: the reference site's CSS, JavaScript, fonts and images; Twig templates; `mtnma.theme` (preprocessing); interface translations (`translations/*.po`, generated by `scripts/build_translations.py`). |
| `web/modules/custom/mtnma_site/` | The site module: content model (`mtnma_site.install`), search hooks, the English redirect, the noindex header, the language-aware link filter, listing definitions, the content extracted from the reference (`content/`) and the seed script. Its README describes each part. |
| `scripts/setup-site.sh` | The setup described above. |
| `composer.json`, `composer.lock`, `.ddev/config.yaml` | PHP dependencies (exact versions) and the DDEV environment. |

### Day-to-day configuration workflow

Configuration lives in the database while the site runs. After changing
settings in the admin UI, export them and commit the YAML changes:

```sh
ddev drush config:export     # database -> config/sync
ddev drush config:import     # config/sync -> database (e.g. after git pull)
```

Content (pages, news, services, menu links, images) is not configuration. The
seed script creates the initial content; content edited afterwards exists only
in that site's database and must be backed up or migrated separately.

## 4. What is not in Git

| Excluded | Why / where it comes from |
|---|---|
| The database | Rebuilt by the setup script. Never commit database dumps; `.gitignore` excludes `*.sql`, `*.sql.gz`, `*.mysql` and `*.zst`. |
| `web/sites/default/files/` | Uploaded and generated files. The 9 content images are recreated from the theme by the seed script; the rest (translations, caches, image styles) is regenerated. |
| `settings.php`, `settings.ddev.php` | Machine-specific settings, generated by DDEV, with database credentials and the hash salt. |
| `vendor/`, `web/core/`, `web/modules/contrib/` | Downloaded by Composer. |
| User accounts and passwords | Created by each environment (see Accounts). |
| The reference ZIP (`mtnma-mauritanie.zip`) | Not needed: its text, links and images are already extracted into the module (`content/`) and theme (`images/`). `scripts/extract_reference.py` re-extracts it if the reference changes. |
| An unused custom block ("Main navigation") | It exists in the original local database but is not placed on any page. |

Node IDs: the section pages and most articles keep the same IDs as the original
site. The RIMER article and the 5 services were created in a different order,
so they have different IDs (`/node/NN`); none of them has a URL alias.

## 5. Comparison with the reference

The reference is the static site in `mtnma-mauritanie.zip` (25 Arabic pages,
25 French pages).

**Matches:**

- All 25 pages exist in both languages: the homepage, 16 section pages and
  7 news articles, plus `article.html`, a duplicate of the RIMER article.
- Visible text matches the reference at 92–100% per page. The header and footer
  match on every page, and articles match fully except the two cases listed
  under "Differs".
- `js/interactions.js`, the fonts and the 19 images are byte-identical.
  `css/styles.css` differs only in its 4 font paths.
- Pages are right-to-left in Arabic and left-to-right in French. Every response
  sends `X-Robots-Tag: noindex, nofollow`, as the reference preview does.

**Differs:**

- `/` opens in Arabic. The reference preview redirects `/` to French.
- The Media Centre lists 7 items (RIMER added), and its filters reload the page
  instead of filtering instantly.
- The gallery shows 6 photos instead of 5, because it lists every article
  photo, including the traffic article.
- The RIMER article has no photo. The ZIP has two versions of it: one uses the
  generic homepage photo, one has none.
- Where the reference uses two wordings, the site uses one: the French
  tenders title, the French university title, and the service names on the
  services page compared with the homepage.
- Public `/en/...` URLs redirect to French. English is an admin-only language.
- The site adds full-text search of pages, news and services, which ignores
  Arabic short vowels and spelling variants.

## 6. Known content limitations

- **Contact:** no address, phone or email. The contact form only copies the
  message to the clipboard; it sends nothing.
- **Organisation chart:** a simplified diagram, not the official chart.
- **Indicators:** archival figures (2021, 2022, and one undated). The homepage
  figures are hardcoded in the theme (`templates/node--front.html.twig`).
- **Tenders:** only expired, archived notices.
- **Laws, strategies and studies:** link to PDFs on the official site; no
  documents are stored here.
- **Articles:** short summaries. RIMER has no photo. The French WFP article
  links to the Arabic original (as in the reference). The minister's biography
  is brief.
- **Gallery:** no videos, only a link to the YouTube channel.
- **Editing:** section-page bodies are raw HTML that only administrators can
  edit. The homepage sections and social links are hardcoded in the theme.
- All ministry content must be checked and approved by the Ministry before any
  public use.

## 7. Browser checks still needed

Automated checks covered HTML, links, translations and the JavaScript logic
(in a simulated browser). Nobody has yet checked these in real browsers
(Chrome, Firefox, Safari, and a phone):

1. Layout and fonts in Arabic (RTL) and French (LTR), at desktop and phone widths.
2. Homepage carousel: animation, auto-advance and pause, swipe on a phone,
   arrow keys following the reading direction.
3. Accessibility panel: larger text and high contrast; keyboard navigation and
   visible focus; a screen-reader pass.
4. Mobile menu, search dialog (page finder and full search), listing filters
   and pager.
5. Contact form "copy" and the article "copy link" buttons.
6. Admin workflow: sign in, edit a news item in both languages, then confirm it
   appears in the listing and in search.

## 8. Deployment and security blockers

None of these has been resolved. The site has not been security-assessed.

1. **No hosting target.** DDEV is a local development tool. A staging host,
   HTTPS, backups, mail and monitoring still need to be defined.
2. **Production settings.** DDEV sets verbose error display, accepts any host
   name and skips file-permission hardening. A shared environment needs
   errors hidden, `trusted_host_patterns` set to its domain, hardened
   permissions, a private files path and real cron.
3. **Installer exposure.** With verbose errors, `/core/install.php` shows a
   stack trace (the Drupal CMS installer packages are present but unused).
   Block it at the web server, or remove the unused packages.
4. **Unused packages.** `composer.json` comes from the Drupal CMS template and
   pulls about 50 packages the site doesn't enable. Trim it, or keep them
   patched (as of 27 October 2026, `composer audit` reports no advisories;
   gin_login, metatag and token_or have non-security updates).
5. **Access control.** Protect any shared environment (for example HTTP
   authentication or a VPN), give each person their own account, and block
   user 1. Keep the noindex header until the Ministry approves publication.
   It asks search engines not to list the site; it does not stop anyone from
   visiting it.
6. **Content and editorial process.** There are no editor accounts or roles,
   no approval workflow, and the missing ministry information listed above.
7. **Security review** of the custom module and theme, the hosting setup and
   the Drupal configuration, before anything is public.

## Verification

On 27 October 2026, the repository files (exactly what a commit contains, with
no database, `vendor/` or uploaded files) were copied to a separate directory
and built as a separate DDEV project with `scripts/setup-site.sh`, then rebuilt
again with `--reinstall`. Results:

- The site installed without errors, apart from the 3 skipped core translation
  strings.
- `drush config:status` reports no differences between the database and
  `config/sync`.
- The rebuild has the same content counts as the original: 29 pages, articles
  and services in Arabic and French, 74 menu-link rows, 46 URL aliases, 9
  images, and 6,978 Arabic and 10,946 French interface translations.
- The admin password is random.
- 66 Arabic and French pages compared with the original site were identical:
  status, `lang`/`dir`, header, page and footer text, links and images. So were
  the 3 English redirects and the 5 service pages.
- Admin pages load in the Claro admin theme. `drush user:login` produces a
  login link.
- No new files appeared that Git would pick up.
